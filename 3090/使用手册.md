# 3090 推理服务使用手册

这份手册只针对 `3090` 文件夹。3090 端负责 Qwen 框选、目标追踪、YOLO 安全检测、运动指令生成、机器人任务状态机，以及向 Windows 网页和树莓派返回状态。

## 1. 启动 3090 服务

在 3090 Linux 主机上运行：

```bash
cd ~/3090
source .venv/bin/activate
python scripts/run_3090_server.py --config configs/linux_3090_remote.yaml --host 0.0.0.0 --port 8000
```

看到下面输出表示服务已启动：

```text
Uvicorn running on http://0.0.0.0:8000
```

本机健康检查：

```bash
curl http://127.0.0.1:8000/health
```

查询 3090 内网 IP：

```bash
hostname -I
```

树莓派和 Windows 通常使用类似 `192.168.55.33` 的内网 IP 连接。

## 2. 主要接口

```text
GET  /health       健康检查
GET  /state        返回轻量状态，不默认携带图片
GET  /stream.mjpg  返回 3090 最新摄像头画面的 MJPEG 视频流
POST /control      接收 Windows 网页控制命令
WS   /camera_ws    树莓派摄像头上传入口
WS   /ws           兼容旧版 Windows 本地摄像头直连模式
```

浏览器可直接测试视频流：

```text
http://<3090内网IP>:8000/stream.mjpg
```

## 3. 单摄像头模式

树莓派单摄像头上传命令示例：

```bash
cd ~/dachuang/linux_camera
source .venv/bin/activate
python scripts/run_camera_client.py \
  --server ws://192.168.55.33:8000/camera_ws \
  --camera 0 \
  --backend v4l2 \
  --width 640 --height 480 --fps 30 \
  --fourcc MJPG \
  --remote-fps 15 \
  --remote-width 640 \
  --jpeg-quality 45 \
  --no-overlay \
  --robot-mode none
```

如果要接入真实小车，把 `--robot-mode none` 改成：

```bash
--robot-mode esp32 --esp32-link ble --esp32-ble-name ESP32-Robot-Car
```

## 4. 双摄像头模式

当前双摄像头模式不做深度估计，只做左右视角判断和目标追踪。树莓派会把左右摄像头拼成一张 side-by-side 图：

```text
左半边 = 小车左摄像头
右半边 = 小车右摄像头
```

推荐启动命令：

```bash
cd ~/dachuang/linux_camera
source .venv/bin/activate
python scripts/run_camera_client.py \
  --server ws://192.168.55.33:8000/camera_ws \
  --left-camera 0 \
  --right-camera 2 \
  --swap-cameras \
  --baseline-mm 120 \
  --backend v4l2 \
  --width 640 --height 480 --fps 30 \
  --fourcc MJPG \
  --remote-fps 15 \
  --remote-width 960 \
  --jpeg-quality 45 \
  --no-overlay \
  --robot-mode none
```

日志中重点看：

```text
left_fps=...
right_fps=...
sent_fps=...
recv_fps=...
server_fps=...
```

建议左右摄像头都接近 15FPS。若左右摄像头反了，可以直接加：

```bash
--swap-cameras
```

`--swap-cameras` 会在拼接前交换左右画面，同时把上报给 3090 的左右摄像头编号也交换。若之后重新接线或改编号后方向正确，就去掉这个参数。

## 5. Windows 网页连接

Windows 只负责显示网页、聊天记录、按钮控制，不直接控制真实小车。

```powershell
cd F:\bigchuang\windows摄像头
.\.venv\Scripts\Activate.ps1
python .\scripts\run_web_console.py --camera-mode remote --server ws://192.168.55.33:8000/camera_ws --host 127.0.0.1 --port 7860
```

浏览器打开：

```text
http://127.0.0.1:7860
```

网页会自动使用：

```text
http://192.168.55.33:8000/stream.mjpg
```

双摄模式下，网页 `Camera View` 会显示：

```text
left     目标在左摄像头画面
right    目标在右摄像头画面
both     目标框跨过左右分界线
unknown  当前没有稳定追踪框
```

双摄模式下，网页会画两类框：

```text
黄/绿实线框   主追踪框，用于控制
蓝色虚线框    paired_track，Qwen 在另一侧摄像头真实识别到目标时才显示，不参与小车控制
```

也就是说：

```text
左右摄像头都看到目标 -> Qwen 返回 left/right 两个真实框，网页两边都锁定
只有左摄像头看到目标 -> 只显示左侧锁定框
只有右摄像头看到目标 -> 只显示右侧锁定框
```

## 6. 3090 返回给树莓派的控制信息

3090 每帧返回结果中包含：

```text
guidance        视觉导航方向和线速度/角速度
safety          是否安全阻塞
robot_task      当前任务阶段
robot_command   给树莓派执行的小车/机械臂命令
```

树莓派端的 `RobotCommandDispatcher` 会把 `robot_command` 转换成 ESP32 协议命令。安全策略在树莓派端继续生效：

```text
safety.blocked=true     停车
emergency_stop=true     停车
subsystem=chassis       输出底盘速度
subsystem=arm/gripper   停底盘后执行机械臂/夹爪动作
```

## 7. 常见问题

### 7.1 树莓派能 ping 通 3090，但 curl 不通

检查代理环境变量，内网地址不要走代理：

```bash
curl --noproxy '*' http://192.168.55.33:8000/health
```

### 7.2 端口 8000 连接拒绝

在 3090 上确认服务是否还在运行：

```bash
ss -lntp | grep ':8000'
curl http://127.0.0.1:8000/health
```

### 7.3 摄像头帧率低

先确认摄像头格式：

```bash
v4l2-ctl --list-formats-ext -d /dev/video0
```

优先使用：

```bash
--fourcc MJPG
```

如果 OpenCV 读取仍然只有 15FPS 左右，可以考虑树莓派端 `scripts/run_mjpeg_camera_client.py` 的 MJPEG 直传脚本。

### 7.4 Qwen 框选失败

可以在 Windows 网页中使用手动 ROI，或点击 `Run Qwen` 重新框选。3090 会在 `/state` 中返回 grounding 状态。

### 7.5 网页视频慢

优先确认浏览器是否直接访问 3090 的 MJPEG 流：

```text
http://<3090内网IP>:8000/stream.mjpg
```

如果这个地址本身流畅，而 Windows 网页慢，再检查 Windows 网页端连接地址和网络路径。

## 8. 推荐启动顺序

1. 启动 3090 服务。
2. 启动树莓派摄像头上传。
3. 打开 Windows 网页控制台。
4. 在网页聊天框输入任务，例如：

```text
捡起垃圾扔进垃圾桶
```

5. 确认目标框、Camera View、Robot Task、Robot Command 都正常后，再切到真实 ESP32 控制模式。

## 双目测距标定入口

如果后续要让双目摄像头做粗略测距，先用棋盘格完成一次双目标定。详细步骤见：

```text
docs/STEREO_CALIBRATION.md
```

树莓派采集左右棋盘格图片：

```bash
cd ~/dachuang/linux_camera
source .venv/bin/activate
python scripts/capture_stereo_calibration.py --left-camera 0 --right-camera 2 --backend v4l2 --width 640 --height 480 --fps 30 --fourcc MJPG --board-cols 9 --board-rows 6 --output outputs/stereo_calibration_samples --count 35
```

3090 计算标定参数：

```bash
cd ~/3090
source .venv/bin/activate
python scripts/calibrate_stereo_from_images.py --input outputs/stereo_calibration_samples --board-cols 9 --board-rows 6 --square-mm 25 --output configs/stereo_calibration.yaml --json-output configs/stereo_calibration.json --preview outputs/stereo_rectified_preview.jpg
```

检查极线校正效果：

```bash
python scripts/check_stereo_calibration.py --calibration configs/stereo_calibration.yaml --left outputs/stereo_calibration_samples/left/left_001.jpg --right outputs/stereo_calibration_samples/right/right_001.jpg --output outputs/stereo_check_rectified.jpg
```

标定输出里的 `baseline_mm_norm` 应该接近实际量到的左右摄像头水平距离；`stereo_rms` 越小越好，粗略测距建议先争取小于 1.0 到 1.5。
