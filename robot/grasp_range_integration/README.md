## 9. 接手同学允许新增的实现

所有新增文件放在：

```text
grasp_range_integration/
├─ README.md                  # 本文
├─ config/                    # 规定距离、容差、速度、安全阈值
├─ adapters/                  # 只读系统输出/ESP32 客户端适配
├─ perception/                # 新增米制相对位姿估计，不改原识别器
├─ controller/                # 正前方对准和短距离闭环
├─ manipulation/              # 经标定的姿态序列与抓取复核
├─ orchestrator.py            # 外层状态机
└─ tests/                     # 纯软件、回放、仿真和硬件分阶段测试
```

推荐外层状态机：

```text
WAIT_SEARCH_SUCCESS
  -> LOCK_CONFIRMED_TARGET
  -> ESTIMATE_RELATIVE_POSE
  -> ALIGN_HEADING
  -> APPROACH_RANGE
  -> STOP_AND_SETTLE
  -> FINAL_VISUAL_AND_RANGE_CHECK
  -> GRASP
  -> VERIFY_GRASP
  -> HOLD_OR_SAFE_STOP
```

### 9.1 输入契约

输入必须至少包含：

- `mission.json` 中任务结果为成功；
- 同一目标的双摄完整确认记录；
- 左右相机原图和对应边界框；
- 拍照时机器人位姿、时间戳及新鲜度；
- 当前雷达前方净空；
- 摄像头内参、双目标定参数和相机到车体/夹爪的外参；
- 当前小车唯一编号及对应机械臂标定文件。

任一输入缺失、过期、置信度不足或机器人编号不匹配时，只能停车并返回失败，不能猜测距离或继续夹取。

### 9.2 必须新增的米制测距

“目标在图像中居中”不等于“目标已进入夹取距离”。需要独立实现并验证下列至少一种米制来源：

1. 标定双目视差/深度；
2. 深度相机；
3. 与相机严格外参标定后的近距离雷达/测距传感器；
4. 经实物尺寸标定且有明确误差上界的单目方案。

建议输出独立数据结构，不改现有检测结果：

```json
{
  "schema": "target_relative_pose.v1",
  "target_id": "stereo_target_1",
  "forward_m": 0.42,
  "lateral_m": -0.03,
  "yaw_error_rad": 0.04,
  "confidence": 0.91,
  "timestamp_s": 0.0,
  "source": "calibrated_stereo",
  "uncertainty_m": 0.03
}
```

### 9.3 规定范围控制

规定距离必须由配置给出，禁止硬编码在模型提示词或识别代码中。例如：

```yaml
target_distance_min_m: 0.35
target_distance_max_m: 0.45
lateral_tolerance_m: 0.03
yaw_tolerance_deg: 5.0
max_approach_speed_mm_s: 100
command_ttl_ms: 300
measurement_max_age_s: 0.30
settle_seconds: 1.0
```

控制要求：

- 先横向/航向对准，再低速接近；不得边快速转向边伸机械臂。
- 只有连续多帧满足距离、横向误差和航向误差，才判定进入范围。
- 每条底盘命令使用短 TTL；测距丢失、目标丢失、雷达近障、通信异常立即 `stop()`。
- 进入范围后必须显式停车并等待稳定，再重新测距和识别一次。
- 夹取期间底盘保持停止；夹取动作不能与导航线程同时占用同一 BLE/串口连接。
- 不得把“超时”当作到位或夹取成功。

### 9.4 夹取动作

- 只能执行当前小车实测并审批的姿态/轨迹，不允许 Qwen 输出关节号、角度或脉宽。
- 所有关节值必须通过机械限位校验；机器人编号不匹配时拒绝执行。
- 推荐序列：`pregrasp -> grasp -> lift -> carry`，但每个姿态必须来自现场标定，不能照抄仿真脉宽。
- 必须有夹取结果复核，例如夹爪反馈、目标随夹爪移动、夹取前后视觉差异等。
- 复核失败时保持底盘停止，停止机械臂并返回结构化失败原因。

## 11. 建议的集成方式

最安全的方式是“外层顺序编排”，而不是侵入原寻物进程：

1. 原系统运行 `natural_search.sh ... real`，完成目标附近搜索并安全停车。
2. 新编排器读取最新 `mission.json`，校验任务成功和双摄证据。
3. 新编排器独占获取底盘/相机/雷达/机械臂资源；获取失败则不动作。
4. 用新增的标定测距模块重新观察同一目标，建立 `target_relative_pose.v1`。
5. 通过现有 `Esp32Client` 的短 TTL 底盘命令进入规定范围。
6. 停车稳定并再次确认目标身份、距离、横向误差和前方净空。
7. 调用新增的、经标定的机械臂适配器夹取。
8. 复核夹取结果，保存完整日志；无论成功或失败，退出前停车并释放资源。

不要让原寻物任务与新控制器同时运行。新模块应复用现有锁，或使用一个覆盖底盘、雷达、双摄和机械臂的更高层独占锁。

## 12. 最低验收标准

### 12.1 纯软件/回放

- 旧的建图、标注、自然语言、寻物测试结果不发生变化。
- 对过期帧、单目命中、双目不一致、低置信度、测距跳变和目标丢失全部拒绝运动。
- 距离控制在仿真/回放中不会越过 `target_distance_min_m`。
- 任一异常路径都会调用底盘停止和机械臂停止。
- 日志记录输入证据、每次测距、控制命令、状态转移和最终原因。

### 12.2 实车分阶段

1. 车轮架空，只验证命令方向、TTL 和急停。
2. 禁用机械臂，仅验证目标正前方对准和规定距离停车。
3. 使用软质假目标，低速重复验证距离误差和不越界。
4. 底盘完全停车后，单独验证当前小车的机械臂标定姿态。
5. 最后才启用完整“接近—停车—夹取—复核”闭环。

实车验收至少应报告：目标距离设定区间、实际停车误差、横向误差、成功率、最大接近速度、急停响应、失败样本及是否发生任何碰撞/越界。
