# 可组合的区域导航、夹取、搬运与地面放置（2026-10-01）

这是机器人运行时技能，不是 Codex 的 SKILL.md。DeepSeek 只解释对象、搜索地点和放置关系；确定性适配器生成步骤、检查资源交接并调用现有底盘/视觉/机械臂程序。它不能生成电机速度、舵机角度、坐标或 shell 指令。

网页仍使用原来的 3090 页面，输入例如：

```text
去柜子边夹取一个绿色小物块，然后放在距离最近的椅子旁
```

确认整轮计划后使用网页的自动执行。搜索未找到时，沿用已有的逐站多角度搜索与恢复；进入示教工作区后，模型重新确认目标中心，完成闭爪抬臂，再前往放置区域。不要在携带中手动点击机械臂复位，因为固件 `#HOME!` 会松爪。

目前支持“地点旁的地面”，不支持“椅子上/桌面上”：后者需要高度和障碍物标定。目标要有明确类别，颜色可省略；仅写“一个物品”不能确定应该夹什么，也不会自动猜成红色小物块。重量/尺寸/形状仍受原夹爪与示教模型的限制。

## 技能与调用链

| 技能 | 作用 | 实现 |
| --- | --- | --- |
| `go_to_region` | 到语义区域旁自由站位，不把家具中心当道路目标 | `pi/region_navigation.py` |
| `find_and_approach` | 指定区域逐站多角度搜索，再视觉靠近示教区域 | 原 phase1 `verified_search` + 原追踪适配器 |
| `model_grasp` | 重新确认双摄中心，模型预测姿态，微下压、闭爪、抬臂 | 原 `arm_teach.py` 模型序列及 s2/s3 微调 |
| `carry_to_region` | 抓取后根据当前雷达定位和 A* 可达路径选择最近地点 | `pi/robot_skills.py` + `region_navigation.py` |
| `place_on_floor` | 到达复核后：闭爪刷新→下臂→松爪→抬臂，不发 HOME | `pi/placement_extension.py` |

完整步骤：读取地图 → 指定区域搜索 → 双摄视觉靠近 → 模型夹取 → 闭爪执行状态核对 → 绑定放置候选 → 携带导航并确定最近可达实体 → 地面放置 → 保存执行结果和照片 → 汇报。

“最近”不是模型在规划时猜一个椅子编号，也不是按原起点选：抓取之后再次取得雷达位姿，比较各候选**旁边自由站位的可达路径长度**，首次确定实体后，恢复时只换该实体旁的站位/角度。地图上的椅子名称优先于旧的几何分类 `category=table`。语义坐标仍是估计，所以携带到达需要至少一个摄像头确认椅子身份；不要求椅子同时进入双摄抓取工作区。

## 减少不必要中断

区域导航复用当前已部署的自适应速度、左右转向经验、雷达运动估计、绕障重规划和换视角恢复，不新建第二个速度控制器。

- 搬运阶段不套用最初的固定起点；上一阶段的位置只是附近 `1.5m` 全朝向定位的 XY 提示，不能作为夹取后实时位姿。新搬运入口先检查四帧雷达强一致并复核评分后新帧，满足后不强制移动验收；不足时复用自适应主动定位/DeepSeek 候选复核。搜索范围外或有效提示缺失不能凭旧位姿盲行。
- 一个角度漏检或视觉接口暂时失败，先完成本站其余方向，再换站位，不直接结束整轮任务。
- 近桌角或站位阻塞进入绕行/换站位恢复，而不是反复尝试同一位置。
- 放置前下臂空间不足，则继续寻找其他站位；实际玻璃墙边界、近障碍、急停及机械臂工作空间限制仍保留。
- 机械臂前后必要停车是资源与动作衔接，不是要求每一帧精准定位。未知通信结果不自动重复抓取/松爪。

有限运行预算用尽、持续无法确认地点或真实障碍没有安全通路时，仍会保留携带状态并给出原因；此实现不承诺取消所有停车，也不能保证任意物品/场景都完成。
