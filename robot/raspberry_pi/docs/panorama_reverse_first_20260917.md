# 前方受阻优先短退（2026-09-17）

## 修改范围

- 根据实时雷达将受阻区分为实际近障碍、只有旧地图受阻、传感器证据不足。
- 雷达确认前方/车身前侧通道受阻时，在选择长距离行驶方向、转向和
  转向额度耗尽判断之前，优先尝试后方安全的短退。没有长距离候选方向，
  不再成为拒绝短退的理由。
- 每次短退的停止目标约 8 厘米，输出和等待时间仍有上限，逐帧复查后方。
  这是雷达里程计下的控制目标，不保证实际机械停止距离恰好为 8 厘米。
  旧地图短段检查由 20 厘米缩至 12 厘米，保留底盘膨胀和停车余量。
- 后方必须有至少 3 个扇区有效回波、整体有效扫描、足够后方/底盘扫掠净空，
  扫描不能过期。后方雷达遮挡、不可信或旧图标出的玻璃墙过近时，不盲退。
  前后物理防撞距离和原车体回波过滤范围没有放宽。
- 接受的后退平移至少 4 厘米时重新选择方向、重置转向额度。
  空转、纯旋转、横向漂移及向前运动不补充后退进展。
  独立后退额度最多连续 3 次，两次之间至少隔 2 秒；
  只有累计确认向前行驶 20 厘米才恢复后退额度，防止反复倒车重置循环。
- 转向额度耗尽、但安全短退重试仍在两秒复查间隔内时，停车刷新扫描，
  不因等待复查立即结束任务。
- 只有地图判断前方受阻、实时雷达显示净空时，先做限时附近定位检查，
  连续可信候选一致才平滑修正；不仅凭一帧地图受阻就后退。
  旧地图可能是在保护玻璃墙，因此不忽略地图障碍，也不直接向前硬冲。
- 连续 3 个完整有输出的行驶窗口无进展时，允许同样受后方防撞约束的
  有限短退恢复。不是根据单帧低位移判断撞墙；无可靠后退条件仍停车。
- 取消原来根据后向目标执行较长倒车的分支，脱困倒车统一走短退入口。
  在 `panorama_motion.jsonl` 记录短退原因、实际估计进展、额度重置以及
  被拒绝的后方保护原因。

原地图、批处理 Qwen 时机不变。本次不修复实车“大转角/方向估计漂移”根因，
也不宣称桌边到玻璃墙边的定位偏差已解决。

## 验证与限制

224 项相关回归测试通过，包含优先级、额度已耗尽时短退、无长方向时短退、
后方遮挡/近障碍/玻璃墙保护、无实际后退不重置额度、连续后退次数上限。
语法检查通过，PGM/YAML 哈希未变。

运行生产状态机在 `ble_scene_17` 旧地图上进行 realistic 扰动仿真，seed=0，
加入 2.1 秒拍摄耗时和 0.25 秒匹配耗时。运动估计是合成模型，
不是实际 ICP；模型不覆盖真实 BLE ACK 中车辆的全部运动响应。

- 后方雷达可见：9 个完整站点、10 次尝试、58 个方向照片，真实几何覆盖
  93.86%、估计覆盖 93.17%，无碰撞，一次模拟卡滞经恢复解除。
  最大照片方向误差 8.47°、最大估计位置误差 0.353 米。
  完整运行出现 67 次短退（额度仅在获得新前进后恢复），仍需优化效率。
- 加入固定车体后方遮挡：7 个完整站点、42 个方向照片，无碰撞，
  真实覆盖 83.28%、估计覆盖 82.59%，最终 `actuator_no_response`。
  `rear_support_missing` 记录 39 次，后方证据不足，因此未执行短退；
  一次模拟卡滞未解除。这个案例没有通过全程验收，不能隐去。
