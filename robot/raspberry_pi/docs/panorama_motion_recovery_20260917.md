# 09-17 起步、停滞恢复与转向修改说明

根据 `inspection_stop_analysis_20260916_plan_20260917.md` 实现的软件版本。
当前仅在本地修改与回归，没有部署、启动实车或进行真实底盘标定。

## 实现内容

### P0：诊断与及时保存

- `panorama_motion.jsonl`：请求/发送输出、TTL、ACK耗时、有限刷新窗口、
  单调时间、扫描采集/接收时间与年龄。没有读取到电机/供电实测反馈时
  字段为 null，发送输出不是实测轮速。
- `panorama_navigation.jsonl` / `live_pose.json`：新增 ICP耗时、上一轮绘图
  耗时、起步恢复次数、重锚次数、位姿不确定标志，以及最终退出原因。
- `panorama_stop_events.jsonl`：保存触发安全停止的原始与过滤后雷达数组，
  以及触发时距离判据，而非只保存停止之后下一帧。
- `panorama_motion_summary.json`：停车后、Qwen开始之前就写出运动结果。
  `panorama_summary.json` 仍是批量识别结束后的完整结果。
- N10在全景运行阶段启用扫描超时上报，断流/无完整扫描约0.5秒时提供空帧，
  使控制器有机会停止和保存；初始定位/普通建图默认不启用，退出时恢复配置。
- 所有新诊断中的非有限浮点数转为 null，禁止把 NaN 当安全无限远。

### P1：共用前进判据

选择器和执行器使用 `_advance_assessment`，检查雷达支持点、传感器安装
偏移、候选方向扫掠通道、地图射线、只读地图短段和扫描时效。
取消直行优先额外0.83m门槛，也允许安全短段小于原0.35m观察地平线，
避免0.78m净空被执行器允许、却被选择器拒绝。

停车基准仍为 `max(stop_distance + 0.30, open_minimum_clearance)`；高于
240mm/s的输出增加速度余量，公式为 `(speed - 240)/1000 × 0.35`。
这是保守的软件余量，不是实测制动模型，现场标定仍须完成。
保持安全直行、±15°、±35°、宽角脱困的分级，覆盖收益不越级抢占。
仅在有限起步和重试确实失败后，才允许拒绝当前方向并尝试另一个出口。

雷达与地图持续相差超过0.6m时保存 `panorama_map_conflicts.jsonl`，最多
每5秒触发近位置核对；冲突核对限制到0.35m、朝向10°，仍需两个一致候选，
不覆盖地图，不直接相信穿透玻璃的雷达回波。

### P2：有限起步与运动窗口

- `STARTING_DRIVE` 默认0.70秒的有效输出窗口；在实时安全判据允许下，
  从现有 `start_kick_speed` 向下每20mm/s选择安全输出，不超过450mm/s。
  例如420不满足0.78m净空的速度余量时，可降到400，而非一律退回240。
- 输出持续以新鲜安全扫描许可为前提，不是睡眠0.7秒盲开。
- 进展判断使用1.80秒有效运动窗口，累计可信相对位移达到0.025m就判为
  有进展；不再用30个低运动决策直接结束整轮，也不以六帧低运动立即卸载。
- 主动停止会暂停窗口；过期输出造成的间断、里程计未知不当作机械故障。
- 第一次窗口停滞同方向起步重试，第二次换出口，第三次仍无位移则明确
  `actuator_no_response` 停车。该名称指前进执行未形成可信位移，不能证明
  电机硬件坏了；电量、物理负载与扫描匹配误差仍需现场区分。

### P3：有反馈的有限转向

- 前方确实可行时优先移动，不以地图角偏差要求原地对准；前方可行时
  也不会仅因侧向空间窄、候选在后方就优先倒车。
- 局部脱困仍每次请求最多20°，但不再假设50～110ms能克服底盘静摩擦。
  无有效转角时使用350ms的有限起步指令，并逐扫描复核；取得角度后
  依据剩余角度选择120～220ms指令。
- 转向无响应需要约1.8秒观察，而非快速收到六帧就判失败。
- 按测得角速度预留4～12°的停止提前量，停止后补计余转。全景和局部
  都使用该流程，仍记录实际照片朝向，不假称请求20°就一定只转20°。
- 局部转向过程中，一旦前方出现安全通道就停止追角度并准备移动。
- 原六次原地脱困预算保留，只有可信前进0.2m才重置，不允许无限换边。

### P4：定位与任务级恢复

- 异常增量仍拒绝，60° / 0.38m上限没有扩大。
- 停车重测约1秒仍失败时，放弃旧扫描参考，保留当前显示位姿、使用新
  静止扫描作为相对跟踪起点；不把被拒绝的变换应用到位置。
- 这会丢失一段运动量，因此明确标记 `pose_uncertain`，置信度上限0.45；
  照片仍保存/识别，但不计入可信几何覆盖。只有一致地图纠正才清除标记。
- 没有可信前进期间最多三次重锚，持续不可用仍安全停车，不无限猜测。
- 没有安全候选持续8秒、雷达过期/无效持续3秒、脱困预算用尽或最终45秒
  没有位置进展仍会停止。不能为了整圈完成绕过真实障碍/玻璃墙/传感器失效。
- Qwen仍在运动停止之后批量执行，原地图和永久占据栅格不写入。

## 指令保活安全边界

Python ESP32客户端新增 `set_bounded_twist`，在ACK事务中原子设置绝对刷新
截止时间；慢ACK不能短暂重新开启无限保活。STOP/取消使当前代次失效。
旧 `set_twist` 的外部使用行为保持不变；无需更改ESP32协议或固件。
指令TTL与最后一次可刷新窗口共同受当前扫描的0.5秒有效期约束；链路异常、
扫描无效、Ctrl+C或危险回波取消运动，不给陈旧指令无限续期。

## 配置

`inspect_map.sh`新增可覆盖的环境参数：

- `PANORAMA_STARTUP_WINDOW_S=0.70`
- `PANORAMA_PROGRESS_WINDOW_S=1.80`
- `PANORAMA_MAX_SCAN_AGE_S=0.50`

对应 `--panorama-startup-window-seconds`、`--panorama-progress-window-seconds`
与 `--panorama-max-scan-age-seconds`。起步输出继续复用已有启动脚本的
`--start-kick-speed`，不要未经标定扩大最高输出或车体回波过滤范围。

## 验证与未完成事项

本轮回归包括真实 MatchResult / ICP接口、0.78m选择器与执行器一致性、
35帧零位移后恢复前进、持续无位移有限重试、重锚不应用异常朝向、陈旧扫描
零运动指令、单个外部近点/玻璃地图防护、断流空帧、慢ACK与STOP并发，
以及原ESP32/协议/链路回归。这些是单元与生产循环分支测试，不是整场仿真。

还没有实测电池状态、最低有效输出、启动延迟、左右转差异、停止余转和
真实制动距离；也没有验证实车整轮覆盖率。下一步应先部署，再在有人看护的
安全条件下只测第一站到第二站，确认诊断和连续运动后再跑全程。

最终本地验证：8组相关回归共206项通过；Python语法、启动脚本语法和
已跟踪改动的空白检查通过。旧 PGM/YAML 的 SHA256 在验证前后相同。
本轮没有运行整场仿真，没有测试实车或推理服务，没有部署。
