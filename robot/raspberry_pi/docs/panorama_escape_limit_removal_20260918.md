# 取消累计脱困额度导致的整轮提前结束

## 失败证据

用户指出能脱困却被旧机制判失效。已读取树莓派 `20260918_194012` 的巡检日志：最终事件 `escape_turn_budget_exhausted`，原因为 `turn_no_response`，6 次转向函数调用累计仅测到约 0.9°，计时约 18.77 秒。不是正常覆盖结束，也不是丢失朝向恢复失败。后方雷达支持缺失，旧逻辑禁止盲倒车；本次不取消这项保护。

小角度转向起步持续输出前一版改为最低 120 ms。它能降低一启动就过冲的风险，但可能无法克服负载下的静摩擦；日志没有独立电机反馈，不能确定所有零转角都代表物理零运动。

## 修改范围

- 累计障碍转向次数、累计转角、累计转向时长和累计无响应计数不再作为后续安全转向的许可门槛，也不再因这些旧额度用完直接结束巡检。
- 删除 `local_escape_turn_budget_exhausted` 与基于旧额度的 `map_guard_no_local_progress` 结束分支；当前方向不安全时停车、重新采样并从当前安全几何重新选向。
- 原 `_EscapeTurnBudget` 只作历史阈值统计；日志 `enforced=false`、`local_escape_limit_policy=telemetry_only_no_mission_cutoff`。可查看旧阈值原因，但它不是正在执行的限制。
- 每次局部转向仍最多请求 20°，有实时雷达净空、扫描新鲜度、质量检查和有限输出 TTL。正常可前进时的可选选向调整仍有独立额度，耗尽后优先安全直行，不结束任务。
- 起步未测到旋转时，依据新的、质量接受的扫描逐渐延长起步脉冲，最低 120 ms，补偿最多 220 ms；转起来后恢复按实际速率与剩余角度控制。输出速度及防撞净空不放宽。
- 保留真正无位置进展 45 秒、持续直行电机无响应、无有效雷达、无安全出口、无法恢复朝向、最大运行时限等独立停车路径。不能把“删除次数判死”理解为无限通电或无限转圈。
- 后退的实时后方净空要求、最多三次未取得前进进展前的后退尝试保持不变。没有有效后方扫描仍不盲倒车。

初始定位、原地图、树莓派任务入口、启动脚本、朝向恢复算法和扫描匹配器不修改。本轮只更新 `open_space_panorama.py`，部署前备份并核对上一轮 19:37 部署回执。
