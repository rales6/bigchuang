# 2026-09-18 行走后定位漂移：局部纠错修改说明

## 适用范围

修正开阔点全景巡检的后续地图纠错，不改变初始定位、拍照顺序、全景转向控制、局部避障、结束判断或停车后批量 Qwen 标注。地图 PGM/YAML 不写入。独立的自然语言任务语义定位模块没有接入本次巡检。

## 本次修改

1. 每个纠错候选保存与其同一帧的里程计位姿。比较两次候选之前，先把前一个地图候选沿中间的相对运动推进到当前时刻，再检查剩余误差是否在 14 cm / 12° 内。正常行驶不再因为两个绝对候选相距较远而误判不连续。真正的候选跳变仍不融合。
2. 停车匹配后继续采集的新鲜扫描可能包含残余运动；将候选推进到返回扫描对应的时刻，避免匹配位姿和里程计位姿时间不一致。地图融合或里程计重新锚定后清空旧候选窗口。
3. 常规低频纠错使用已配置的局部半径，内部最大半径 65 cm，不再一律截断为 35 cm。常规朝向搜索仍为 ±15°；冲突检查仍可指定较小平移范围，不做全图重定位。
4. 累计实际扫描匹配转角达到 45° 后，主循环在进入后续动作前尝试一次停车朝向校准。全景拍照内部不逐张插入校准，整站结束后再检查。两次检查至少间隔 8 秒；检查失败也消耗本次触发，不在原地立即重试。
5. 朝向校准只在附近 18 cm / ±45° 搜索，采集两帧独立扫描，要求质量达标且经运动补偿后一致。只融合朝向的 35%，每次最多 12°；不因地图匹配修改当前位置，也不把地图纠正角当作真实底盘转角喂入局部航向锁。
6. 朝向检查采用共享的 2 秒协作式预算，单次地图匹配预算 0.35 秒；不发送转向/平移指令，不调用 Qwen，不因校准失败中止任务。传感器取帧本身的阻塞时间无法由此预算硬中断。返回运动前继续遵守扫描新鲜度检查。
7. 地图和实时雷达明显冲突，或常规纠错连续多轮失败时，显示/照片记录位姿不确定，但不额外增加停车保护或转圈。只有可信的完整位姿纠错确认后才清除此标记。

## 日志

`panorama_motion.jsonl` 新增/扩展：

- `map_correction`：候选坐标、质量、相对当前位姿的偏差和搜索状态。
- `map_correction_validation`：质量不足、位置越界、朝向越界、等待第二候选、补偿后仍不一致等具体原因；同时保存补偿后的剩余位置/朝向误差。
- `heading_calibration`：检查结果、耗时、融合角度、候选和搜索状态。

`live_pose.json` 和导航记录增加 `last_heading_calibration`。搜索返回候选不等于候选已经被接受/融合，需结合 validation 事件查看。

## 验证与限制

- 定位与巡检相关单元回归：206 项通过，其中本次新增 13 项。
- 使用旧 `ble_scene_17` 地图真实匹配器，加入 8 mm 距离噪声、3% 丢点和 ±24°～39° 朝向偏差，6 组局部搜索均找回正确附近朝向，候选残差角为 0°～1°。这验证的是候选搜索，不代表一次受 12° 限幅的融合就能消除全部误差，也不是实车验证。
- 全景生产状态机的 realistic / 车体回波扰动仿真：3 组均无碰撞，但都因 `local_escape_turn_budget_exhausted` 未完成整圈；修改前部署版本相同 3 组也都出现该结束原因。新版本实际覆盖率约 64%、73%、93%，旧版约 76%、93%、80%。轨迹/RNG 消耗不同，不能据此宣称覆盖表现无回退或全程验收通过。
- 此整圈仿真的雷达里程计是合成运动估计，不评估真实 ICP 累计漂移；局部搜索噪声实验使用真实地图匹配器，但雷达数据由旧地图生成，未证明玻璃穿透、动态障碍、机械卡住等实车情形均已解决。
- 原地图哈希保持一致；历史照片、原有标注结果不覆盖、不自动删改。本次只完成本地修改，没有部署或启动实车。
