# ESP32 运动参数拒绝修复（2026-09-17）

实车日志 `inspection_logs/inspect_map_20260917_152247.log` 报 `ESP32 拒绝 type=0x13，错误码 4`。`0x13` 为四轮补偿运动指令，4 为参数值错误。

对应 `inspections/ble_scene_17/20260917_152248/panorama_motion.jsonl` 中失败指令：线速度 420、角速度 342、扫描年龄 0.453872572 s、TTL 46 ms。此前旋转 TTL 204 ms 多次接受。明显异常是雷达新鲜度预算将正常 TTL 截短到了 46 ms；未取得固件源码确认其精确下限，因此采用保守 100 ms 兼容下限。

## 修改

- 剩余雷达有效时间或请求 TTL 少于 100 ms 时，记录 `command_deferred/scan_budget_too_short`，停车，不发送运动指令。不向上补齐 TTL、不绕过雷达有效期。
- 直行取新扫描后继续原流程，界面显示 `WAIT_FRESH_SCAN`，不因本地延期触发 ESP32 参数拒绝。
- 原地旋转遇到同样情况，停车刷新扫描，补计停车期间经验证的转角，再继续本次旋转；不因旧帧预算不足直接把全景判为失败。
- 真正通信拒绝/断链仍停车并上报，日志新增具体异常文本；不无限重试不合法指令。
- 回归精确复现 46 ms 失败条件，断言没有运动输出；换到新扫描后恢复合法 TTL。同时检验短 TTL 请求不会被擅自延长。
- 部署只读检查包含相同复现，不调用 ESP32、不启动相机/雷达/电机。

本次部署同时包含上一轮已完成的 24×22 cm 外廓配置和地图保护限次重新选向修改。其限制见 `panorama_footprint_24x22_20260917.md`：后方遮挡的完整任务测试仍未通过，不能宣称本次参数修复保证跑完一圈。
