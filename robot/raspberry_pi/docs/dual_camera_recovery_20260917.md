# 双 USB 摄像头取帧修复与实机检查（2026-09-17）

## 本次故障

用户日志 `inspection_logs/inspect_map_20260917_184544.log` 在相机自检阶段报错
`两路摄像头未能在超时前同步取得图像`，尚未开始定位和巡检运动。

旧程序每轮必须同时成功 grab 两路，才 retrieve 两路；任一路短暂失败，另一路
成功帧也被丢弃。每次拍照均重新打开、配置并关闭两路 UVC 摄像头。

## 修改范围

仅修改 `raspberry_pi/map_camera_inspection.py` 的相机采集及资源释放逻辑：

- 每路独立 grab/retrieve，保留成功帧；不再要求同一次循环两路都成功。
- 使用主机 grab 完成时间约束新鲜度与两路时间差（均不超过 0.75 秒）。
  这不是硬件曝光同步，不声称两路曝光时间完全一致。
- 双摄缓冲由 1 改为 3；保持 MJPG、原分辨率及帧率，不降为单摄。
- 巡检拥有的双摄对象保持两路设备打开，避免每张照片重复协商 UVC 参数。
  每次采集至少取四帧，丢弃三缓冲队列中的旧帧后才保存照片。
- 单路连续失败时，只重新打开失败路一次；共享原有采集超时预算。
- 设备掉线、路径消失和重新打开失败保留到分路诊断中，不再掩盖原始问题。
- 超时输出每路帧数、grab/retrieve 失败次数、格式、重开次数及最后错误。
- 正常结束、异常退出、单独相机测试结束均释放程序自己持有的相机。
  外部传入的相机仍由调用者负责释放；`close()` 可重复调用。

底层 V4L2 调用可能阻塞，预算仍是软超时，并不是强制终止驱动调用的硬超时。
没有修改定位、运动、地图文件、碰撞保护或照片标注逻辑。

## 验证及未解决事项

本地相机回归 12 项及导航/通信等回归合计 248 项通过。

通过 SSH 仅在临时 Python 进程内加载修改后的相机类，未替换树莓派生产代码，
未启动电机、雷达或完整巡检任务。检查期间没有巡检进程占用相机。

实际发现：

- 两路独立顺序取帧曾均成功；底层第二路 V4L2 三缓冲采集也曾连续取得三帧。
- 使用三缓冲的一次双摄测试成功（1.65 秒），但随后重新打开第二次失败。
- 加入持久流后尝试三次连续拍照，仍在第一对照片阶段失败，不能宣称实机修复通过。
- 最后一次诊断：第一路取得 331 帧，第二路 0 帧，且第二路稳定设备路径消失。
- 内核存在第二路 `Failed to set UVC probe control : -71`、设备描述符读取错误、
  USB reset/disconnect、重新枚举记录。第二路不是单纯“两路同步过于严格”。
- `vcgencmd get_throttled` 为 `0x0`，但这不能排除相机端连接、线材或供电问题。

需要先重新插牢第二路 USB 摄像头，必要时更换线缆/USB 接口，再做连续双摄拍照
验证。当前没有擅自复位 USB、重启机器或杀死其他相机进程。

代码修复已在本地，尚未部署；应在第二路硬件连接稳定后部署并再次验证。
