# 维护与恢复

- 新主仓库：`robot-car/`，保留 `car1.0` 的原 Git 历史。原整理阶段未提交推送；2026-10-16 应用户要求准备上传独立交接分支 `handoff/20261016`，见 [GitHub交接说明](../handoff_github.md)。
- 收回过程仅通过 SFTP 读取源码和当前地图，未修改远端文件，未调用实车动作。
- `source_manifest.json`：同步时文件来源与哈希。文件后续有意修改时哈希可以变化，不将它当软件签名或实车验收。
- 旧工作区放在仓库外 `_archive/`，具体位置以 `workspace_archive.json` 为准；没有证明无用的源码不永久删除。
- 当前 13 个旧项目/文件已归档；`car1.0` 被其他进程占用，保留原位，不强制结束进程。主开发入口统一使用 `robot-car/`。
- 设备上的旧地图、照片、录像和任务结果保持原样；它们不是当前仓库依赖。
- 当前地图、示教元数据和必要小夹具保留；大模型、日志、缓存和虚拟环境由 `.gitignore` 排除。

`tools/maintenance/assemble_workspace.py` 是此次一次性收回工具：需要显式 `--apply`，存在来源清单后拒绝覆盖，防止后续工作被旧同步脚本重置。设备密钥指纹固定，密码只从环境变量取得。

不要直接运行旧的 `robot/tools/deploy_*` 来发布新目录：那些脚本仍描述原设备布局。正式部署前应按来源清单准备明确发布包、检查差异、备份并确认设备空闲。本次不包含任何部署操作。

具体检查结果和兼容改动见 [validation.md](validation.md)。
