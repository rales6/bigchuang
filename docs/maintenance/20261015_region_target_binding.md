## 修改范围

- 目标绑定仍是首次选中的地图实体，换观察角度/站位不更换柜子；视觉上下文和到达证据显式带 `map_entity_id`。
- 到达只使用结构化物体颜色；有结构化颜色时，不用外观指纹覆盖它；绝不从自由描述抽取标签/旁边物品的颜色。拒绝柜子类别与描述主体“门/窗/墙”明确矛盾、以及全画面大框的结果。单摄仍然可以确认，不新增双摄同时看见家具的要求。
- 到达还核对当前估计朝向与原地图目标区域是否相容，带地图不确定度及相机安装余量；前方任意家具不能确认车后方的地图目标。它是粗略区域约束，不要求逐帧精确定位，不将估计距离冒充实测深度。
- 全局候选描述增加门/窗/楼梯的全方向方位，包括相机后方。至少两次复核、真实不同双摄图片下，高置信度“确实看到”的稳定地标可排除粗大的前后矛盾。**没看到**不用于否定候选；延展玻璃墙不按标注中心点裁判左右；不确定度圆内的点不用于方向否定。
- 即使模型弃选，也保留正向约束；剩余雷达候选形成连贯的近邻/朝向范围时，使用其粗略范围搜索并继续四帧及新帧雷达复核。标记为 `positive_structure_constrained_lidar`，不冒充视觉唯一定位。远处分散候选不压成一个“确定”坐标；没有取消障碍/玻璃保护或修改雷达正反方向。
- 每个任务 JSON 增加 `initial_localization`、`route_history`、`execution_trace`：分别保留起步证据来源、原路线及重规划路线、下发跟踪的路点/估计位姿/线角速度。记录不替代原路线控制器、不发运动指令；轨迹明确是估计值，不是外部实测真值。
