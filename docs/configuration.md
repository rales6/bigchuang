# 运行配置

仓库提供程序与配置模板。实际地图、模型、相机标定及连接参数需按部署环境准备；安装Python依赖并不能替代这些运行依赖。

## 地图与场景数据

`maps/current/` 是场景数据的放置约定。也可通过各组件的运行配置指向已有发布目录。准备雷达地图、语义布局、定位参考及对应发布清单，并核对它们属于同一版本。

玻璃边界必须与地图匹配，不应从其他场景直接复制。需要运行录制回放时，按测试入口配置相应夹具；未配置数据的专用用例会跳过。

## 模型与相机

机械臂模型权重与元数据由模型服务加载；模型必须与相机左右顺序、安装位置和设备标定匹配。Qwen/YOLO模型及依赖按感知组件的说明准备。

标定、模型权重和设备学习状态不属于通用源码依赖，按部署环境单独管理。

## 网络与访问配置

文档中的 `192.0.2.*`、`198.51.100.*`、`.example.invalid`、`/home/robot` 和 `/home/gpu` 均为示例，需替换为实际配置。

`.env.example` 列出可用变量名，应用不会自动加载该文件。应通过启动进程环境或对应服务配置传入参数。维护工具使用的连接变量包括：

| 变量 | 用途 |
| --- | --- |
| `PI_HOST`、`PI_USER`、`PI_SSH_PORT` | 树莓派连接 |
| `GPU_HOST`、`GPU_USER`、`GPU_SSH_PORT` | GPU服务器连接 |
| `PI_SSH_PASSWORD`、`GPU_SSH_PASSWORD` | SSH认证 |
| `PI_SSH_HOST_KEY_SHA256`、`GPU_SSH_HOST_KEY_SHA256` | 经独立核验的SSH主机指纹 |

API配置按任务规划/视觉组件的入口设置。使用自己的凭据，通过本地环境或配置文件提供，不写入源码。具体要求见[协作约定](../CONTRIBUTING.md)。

## 服务与状态

分别核对Pi桥、反向隧道、GPU网页、感知服务和机械臂服务的路径与端口。避免在同一设备重复启动同类服务。

速度学习状态和任务录像属于运行数据。更新代码时保留需要继承的设备状态，不用Git重置已标定参数。服务启动和健康检查命令见[README](../README.md)。
