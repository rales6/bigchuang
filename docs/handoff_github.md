# 下一组同学：公开源码与内部资料分别交接

先读[根 README](../README.md)、[功能索引](features.md)、[组件边界](architecture.md)和[依赖说明](../requirements/README.md)。公开仓库提供算法、服务、手机端、固件、仿真和测试源码，不提供可以直接访问原设备的配置。

## 获取公开版

```bash
git clone https://github.com/rales6/bigchuang.git robot-car
cd robot-car
```

本次清理通过 `privacy/20261016` 分支和拉取请求交付；合并前应显式切换到该分支。旧交接分支与旧提交可能仍含内部资料，不能因为最新目录已经删除就当作历史已清理。

## 向项目负责人单独取得

- 当前雷达/语义地图、发布哈希、视觉定位参考照片。
- 与该地图绑定的玻璃边界及内部雷达回放夹具。
- 当前机械臂模型权重与元数据、相机标定和设备参数。
- 自己有权使用的设备账号、网络地址、SSH主机密钥指纹和API配置。
- 当前设备的速度学习状态及需要保留的运行经验。

这些文件已经从公开版本移出，原成员本地有内部备份。不要把内部包再次推送到GitHub。取得授权后按对应忽略路径放置数据，或配置运行端已有发布路径；不要把整个内部源码快照覆盖进公开工作区。

## 安装、验证、运行

先按README运行离线检查。没有内部数据时，录制/地图专用测试会明确标记跳过。补齐内部资料后，可以在内部环境进行回放和实机验收；公开CI通过并不证明实车任务完成。

文档、脚本中的网络和家目录均是示例，换成自己的配置前不要运行部署工具。相机顺序、舵机标定、模型和玻璃包络必须以设备上经过验证的内部版本为准。实际动作需安排现场看护，不能为了恢复网页直接启动寻物或重置机械臂。

API密钥不随仓库提供。原成员应自行撤销旧密钥，新成员使用自己的密钥，并检查每个浏览器本地存储。仅删除JSON中的密钥不会撤销供应商账户中的密钥。
