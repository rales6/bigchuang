# 系统架构与职责边界

## 总体数据流

```mermaid
flowchart LR
    APP["手机 App\n自然语言、视频、地图 UI"]
    PI["树莓派\n摄像头、雷达定位、地图、千问、任务规划"]
    ESP["ESP32\n安全校验、速度控制、机械臂、IO"]
    BUS["现有电机底板\n旧 ASCII UART"]
    MOTOR["四轮电机/底板"]
    ARM["六关节机械臂"]

    APP <-->|"Wi-Fi / 互联网\n视频与高层数据"| PI
    PI <-->|"专用 UART（主）/ BLE（备用）\nVehicle Link V2"| ESP
    ESP -->|"UART2\n#000–#009"| BUS
    BUS --> MOTOR
    BUS --> ARM
```

App 发出的“帮忙收拾东北角的物块”不会直接进入 ESP32。树莓派结合相机、
雷达定位、既有地图和执行进度调用千问，输出短周期的确定性动作，例如：

1. `SET_TWIST(250 mm/s, 0 mrad/s, TTL=600 ms)`；
2. 收到新图像与定位后重新规划；
3. `SET_TWIST(120 mm/s, 700 mrad/s, TTL=600 ms)`；
4. 到达物块后发送多个关节目标；
5. 持续读取 `ROBOT_STATUS` 判断动作是否接受、执行器是否异常。

ESP32 不负责理解东北角、物块、自然语言或地图坐标，只负责安全地执行数值命令。

## 树莓派—ESP32 链路选择

| 方案 | 优点 | 风险/代价 | 本项目定位 |
|---|---|---|---|
| 专用 UART | 延迟稳定、协议简单、不依赖配对和网络、车内短线可靠 | 需要两根信号线和共地 | **主控制链路** |
| 蓝牙/BLE | UART 断线后仍可传输同一控制帧，也便于无线调试 | 首次发现和连接较慢，存在射频干扰 | **已实现的备用链路** |
| Wi-Fi | 带宽高、适合视频与 App | 与视频抢带宽；网络切换、拥塞不适合最终急停链路 | App↔树莓派 |

标准 ESP32 提供多个 UART 控制器，树莓派链路和执行器链路应物理隔离。ESP32 的
Wi-Fi 与蓝牙共享射频资源并按时隙共存，因此不建议让同一 ESP32 同时承担视频
网络和实时底盘控制。参考：[ESP32 UART 官方文档](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/peripherals/uart.html)、
[ESP32 RF 共存官方文档](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-guides/coexist.html)、
[Raspberry Pi UART 配置](https://www.raspberrypi.com/documentation/computers/configuration.html)。

ESP32 同时轮询 UART 与 BLE，UART 在同一轮询周期中优先；每条响应返回产生请求的
链路。树莓派 `auto` 模式先使用 UART，超时或读写错误后才建立 BLE 连接。重试沿用
原序号，ESP32 的幂等缓存可防止“命令已执行但 ACK 丢失”时重复动作。

## UART 分配

| 端口 | 用途 | 默认引脚 | 允许的来源 |
|---|---|---|---|
| UART0 | REPL/日志 | 开发板默认 | 调试终端，不承载协议 |
| UART1 | 树莓派控制 | TX22 / RX21 | 仅 `SRC=0x10` |
| UART2 | 执行器总线 | TX17 / RX16 | 配置过的底板/电机节点 |

即使某一帧 CRC 正确，来源地址不符合物理端口也会被丢弃。这样不会把底板反馈误
当成树莓派命令，也不会把 K210 遗留数据误当作电机状态。

## 当前执行器接口

当前底板是写入式旧协议：ESP32 发送四个电机通道命令，底板不返回标准 ACK 或
状态。为了避免速度积压，适配器只保留最新速度；停止指令使用最高优先级。六个
舵机也使用同一 UART 的 ID000–005。调度器每轮最多写一个完整命令组，机械臂新
目标按 `#255PDST!` → 新关节目标的顺序抢占，避免电机和舵机字符串交叉写入。

因此当前状态里的轮速和电池电压没有真实来源。应用不能把零值解释为“轮子确实
静止”或“电池电压为零”，只能把它解释为“当前硬件未提供反馈”。

## 可选 V2 执行器总线规则

1. ESP32 是唯一主机，从节点不得主动发送。
2. 从节点只响应 `DST` 等于自身地址且要求应答的帧。
3. 同一时刻最多一个可靠请求在途。
4. ESP32 按节点地址轮询状态；每次只允许被轮询节点响应。
5. 35 ms 未响应会重试，最多两次；失败计入状态中的 `bus_errors`。
6. 连续速度命令不等待 ACK，只保留最新未发送速度，避免旧速度排队。
7. 停止命令使用最高优先级；机械臂新目标会排入“停止旧动作→新目标”。

未来若四个电机是独立 UART 节点，需要为它们配置唯一地址 `0x31`–`0x34`，并把
地址加入 `ACTUATOR_NODE_ADDRESSES`。若底板统一管理全部执行器，保留默认
聚合地址 `0x30` 即可。不要把多个普通推挽 TTL TX 引脚直接并联；真正的多点
物理总线应使用 RS-485 等合适的收发器和方向控制。当前默认推荐由聚合底板只用
一对 UART 与 ESP32 通信，再由底板管理四个电机。
